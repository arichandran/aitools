## <a id="_Toc239677969"></a>1\. Detailed Unit Content

### <a id="_Toc239677970"></a>2\.1 Anatomy of a Good Prompt

A prompt is the instruction a user gives to a generative AI model. Because LLMs generate text by predicting the most statistically plausible continuation (see Unit 1, Section 1.3), the quality and specificity of the prompt directly shapes the quality of the output — this discipline is called prompt engineering. A well-formed prompt typically contains four components:

  <thead>
    <tr>
      <th style={{ textAlign: "center", width: "80px" }}>Sl. No.</th>
      <th>Component</th>
      <th>Purpose</th>
      <th>Example</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td style={{ textAlign: "center", fontWeight: "bold" }}>1</td>
      <td><strong>Context</strong></td>
      <td>Gives the model background it needs to tailor the answer.</td>
      <td>"I am a first-year B.Tech CSE student preparing for a viva."</td>
    </tr>
    <tr>
      <td style={{ textAlign: "center", fontWeight: "bold" }}>2</td>
      <td><strong>Clear instruction</strong></td>
      <td>States exactly what action the model should perform.</td>
      <td>"Explain binary search and its time complexity."</td>
    </tr>
    <tr>
      <td style={{ textAlign: "center", fontWeight: "bold" }}>3</td>
      <td><strong>Desired format</strong></td>
      <td>Specifies how the answer should be structured.</td>
      <td>"Answer in 5 bullet points, each under 20 words."</td>
    </tr>
    <tr>
      <td style={{ textAlign: "center", fontWeight: "bold" }}>4</td>
      <td><strong>Constraints</strong></td>
      <td>Limits scope, length, tone, or excluded content.</td>
      <td>"Do not use any mathematical notation; use plain English only."</td>
    </tr>
  </tbody>
</table>

Combining all four into a single prompt produces dramatically better output than a bare instruction alone. Compare: 'Explain project scheduling' (vague) versus 'As a project-management tutor, explain project scheduling to a first-year engineering student in 4 bullet points, using a simple campus-event example, avoiding technical jargon' (well-formed).

### <a id="_Toc239677971"></a>2\.2 Zero\-Shot, Few\-Shot, and Chain\-of\-Thought Prompting

Prompting strategies differ based on how much guidance and structure is provided to the model:

  <thead>
    <tr>

  <tbody>
    <tr>

      <td>Common, straightforward tasks with standard outputs (translation, calculation).</td>

__Illustrative Prompts by Technique:__

*Zero-shot example:*
> "What is 15% of 240?"

*Few-shot example:*
> "Convert the following into a formal tone:  
> Input: 'hey can u send the file' -> Output: 'Could you please share the file?'  
> Input: 'wanna meet tmrw?' -> Output: 'Would you be available to meet tomorrow?'  
> Input: 'the report is late again' -> Output: ?"

*Chain-of-thought example:*
> "A tank fills at 12 litres/min and drains at 4 litres/min simultaneously. How long to fill a 480-litre tank? Think step by step before answering."

### <a id="_Toc239677972"></a>2\.3 Role\-Based and Context\-Setting Prompts

A role\-based prompt asks the AI to adopt a persona or professional stance before answering — e\.g\., 'Respond as a strict viva examiner', 'Act as a senior software engineer reviewing my code', or 'You are a patient tutor explaining this to a beginner'\. This technique works because it narrows the space of plausible continuations toward the tone, vocabulary, and priorities associated with that role in the model's training data\. Context\-setting prompts similarly narrow the answer by describing the situation \(audience, purpose, prior knowledge level\) even without an explicit persona\.

__Caution:__

A role\-based prompt changes tone and framing, but it does not grant the model new factual knowledge or guarantee accuracy — a model asked to 'act as a doctor' is still an LLM predicting plausible text, not a licensed physician\. Output must still be verified \(see Unit 5\)\.

### <a id="_Toc239677973"></a>2\.4 Iterative Prompt Refinement

Rarely does the first prompt produce the ideal answer. Iterative refinement is the practice of diagnosing what is wrong with a response (too vague, wrong format, missing an aspect, wrong tone, factually shaky) and rewriting the prompt to fix that specific issue, one change at a time, so the student learns which prompt element caused which improvement.
