Tools like GitHub Copilot and Cursor work inline inside an editor, suggesting completions as the student types, while conversational tools (ChatGPT, Claude) work through a chat interface where the student pastes code and describes the problem. Claude Code and similar agentic tools go further, autonomously reading multiple files in a project, running the code, and iterating on fixes with minimal step-by-step guidance.

### <a id="_Toc239677997"></a>4\.2 AI Writing Assistants for Reports, Emails, and Documentation

Writing assistants help at every stage of producing a document: drafting an initial structure, expanding bullet points into full prose, checking grammar and tone, and adapting formality for the audience \(a professor vs a company recruiter vs a teammate\)\. The key skill is prompt specificity about audience and purpose — 'write a formal report' produces a different document from 'write a two\-paragraph informal update for my project teammates'\.

### <a id="_Toc239677998"></a>4\.3 AI Tools for Scheduling, Note\-Taking, and Meeting Summarisation

Tools such as Notion AI and Fathom can transcribe a lecture or meeting recording, extract action items, and generate a concise summary automatically\. This reduces the manual burden of note\-taking, but the source recording \(or the student's own notes\) should be retained so any AI summarisation error can be traced back and corrected\.

### <a id="_Toc239677999"></a>4\.4 AI\-Assisted Presentation and Slide\-Outline Generation

Given a topic and target duration, tools such as Gamma or a conversational AI can propose a slide\-by\-slide outline \(title, 3\-5 bullet points per slide, suggested visual\) along with speaker notes\. This accelerates the earliest, often most time\-consuming part of preparing a presentation — organising content into a logical sequence — leaving the student to focus on refining content accuracy, visuals, and delivery\.

### <a id="_Toc239678004"></a>Experiment 3: Write and Debug a Simple Program Using an AI Coding Tool

Problem: Use an AI coding tool to write and debug a simple program for a given problem statement.

__*Step-by-Step Solution*__

Problem statement: Write a program that checks whether a given number is prime.

```python
# Initial AI-generated version (contains efficiency limitation)
def is_prime(n):
    if n < 2:
        return False
    for i in range(2, n):        # checks up to n-1 unnecessarily
        if n % i == 0:
            return False
    return True

print(is_prime(1))   # False
print(is_prime(2))   # True
```

Testing reveals `is_prime(1)` correctly returns `False` and `is_prime(2)` returns `True`, but the loop `range(2, n)` is inefficient for large n.

Debugging / optimisation prompt: `"This prime-checking function works correctly but is slow for large numbers. Optimise it."`

```python
# Optimised version
def is_prime(n):
    if n < 2:
        return False
    for i in range(2, int(n ** 0.5) + 1):   # only check up to sqrt(n)
        if n % i == 0:
            return False
    return True
```

**Algorithm Optimization Comparison:**

  <thead>
    <tr>
      <th style={{ textAlign: "center", width: "80px" }}>Sl. No.</th>

      <th>Time Complexity</th>
      <th>Performance & Scalability</th>
    </tr>
  </thead>

    <tr>
      <td style={{ textAlign: "center", fontWeight: "bold" }}>1</td>
      <td><strong>Initial Draft</strong></td>
      <td><code>range(2, n)</code></td>
      <td>O(n)</td>
      <td>Inefficient: Checks redundant factors beyond √n; slows noticeably for large numbers.</td>

    </tr>
  </tbody>

__*Explanation of Approach*__

Correctness and efficiency are two separate concerns: the original code was not factually wrong, but was needlessly slow, since any factor larger than the square root of $n$ must pair with a factor smaller than the square root — checking beyond √n is redundant. This distinction (bug vs inefficiency) is an important lesson for beginner programmers.
