# <a id="_Toc239677994"></a>UNIT 4: AI Tools for Coding, Writing, and Productivity

## <a id="_Toc239677995"></a>1\. Detailed Unit Content

### <a id="_Toc239677996"></a>4\.1 AI Coding Assistants: Generation, Explanation, and Debugging

AI coding assistants operate at three levels of support: \(a\) code generation — writing new code from a natural\-language description; \(b\) code explanation — describing what an existing, possibly unfamiliar, piece of code does line by line or as a whole; and \(c\) debugging — identifying why a program produces incorrect output or crashes, and proposing a fix\. Tools like GitHub Copilot and Cursor work inline inside an editor, suggesting completions as the student types, while conversational tools \(ChatGPT, Claude\) work through a chat interface where the student pastes code and describes the problem\. Claude Code and similar agentic tools go further, autonomously reading multiple files in a project, running the code, and iterating on fixes with minimal step\-by\-step guidance\.

### <a id="_Toc239677997"></a>4\.2 AI Writing Assistants for Reports, Emails, and Documentation

Writing assistants help at every stage of producing a document: drafting an initial structure, expanding bullet points into full prose, checking grammar and tone, and adapting formality for the audience \(a professor vs a company recruiter vs a teammate\)\. The key skill is prompt specificity about audience and purpose — 'write a formal report' produces a different document from 'write a two\-paragraph informal update for my project teammates'\.

### <a id="_Toc239677998"></a>4\.3 AI Tools for Scheduling, Note\-Taking, and Meeting Summarisation

Tools such as Notion AI and Fathom can transcribe a lecture or meeting recording, extract action items, and generate a concise summary automatically\. This reduces the manual burden of note\-taking, but the source recording \(or the student's own notes\) should be retained so any AI summarisation error can be traced back and corrected\.

### <a id="_Toc239677999"></a>4\.4 AI\-Assisted Presentation and Slide\-Outline Generation

Given a topic and target duration, tools such as Gamma or a conversational AI can propose a slide\-by\-slide outline \(title, 3\-5 bullet points per slide, suggested visual\) along with speaker notes\. This accelerates the earliest, often most time\-consuming part of preparing a presentation — organising content into a logical sequence — leaving the student to focus on refining content accuracy, visuals, and delivery\.

### <a id="_Toc239678000"></a>4\.5 Integrating AI Tools into a Day\-to\-Day Academic and Engineering Workflow

A mature AI\-augmented workflow assigns each stage of a task to the tool best suited for it \(see Unit 1, Section 1\.4 selection criteria\), while keeping a human decision point at the end of every stage\. A typical weekly student workflow might look like:

__Stage__

__Tool Type__

__Human Checkpoint__

### <a id="_Toc239678004"></a>Experiment 3: Write and Debug a Simple Program Using an AI Coding Tool

Problem: Use an AI coding tool to write and debug a simple program for a given problem statement\.

__*Step\-by\-Step Solution*__

Problem statement: Write a program that checks whether a given number is prime\.

\# Initial AI\-generated version \(contains an off\-by\-one bug\)

def is\_prime\(n\):

    if n < 2:

        return False

    for i in range\(2, n\):        \# bug: should stop at sqrt\(n\), and range\(2, n\) misses n\-1 as a valid non\-factor check is fine, but inefficient AND fails for n where n itself equals a boundary — real bug demo below

        if n % i == 0:

            return False

    return True

 

print\(is\_prime\(1\)\)   \# should be False \-> check

print\(is\_prime\(2\)\)   \# should be True

Testing reveals is\_prime\(1\) correctly returns False and is\_prime\(2\) correctly returns True, but the loop range\(2, n\) is inefficient for large n \(checks up to n\-1 unnecessarily\)\. Debugging prompt: "This prime\-checking function works correctly but is slow for large numbers\. Optimise it\."

\# Optimised version

def is\_prime\(n\):

    if n < 2:

        return False

    for i in range\(2, int\(n \*\* 0\.5\) \+ 1\):   \# only check up to sqrt\(n\)

        if n % i == 0:

            return False

    return True

__*Explanation of Approach*__

Correctness and efficiency are two separate concerns: the original code was not factually wrong, but was needlessly slow, since any factor larger than the square root of n must pair with a factor smaller than the square root — checking beyond √n is redundant\. This distinction \(bug vs inefficiency\) is an important lesson for beginner programmers\.

### <a id="_Toc239678005"></a>Experiment 4: Draft a Formal Email or Report and Manually Edit It

Problem: Draft a formal email or short report using an AI writing assistant, then manually edit it for accuracy and tone\.

__*Step\-by\-Step Solution*__

Scenario: requesting a one\-day extension for a lab report submission\.

AI\-drafted version \(typical first pass\):

__AI Draft:__

"Dear Sir/Madam, I am writing to request an extension for my lab report submission due to unforeseen circumstances\. I would be grateful if you could grant me one additional day\. Thank you for your understanding\. Sincerely, \[Name\]"

Manual edit for accuracy and tone \(student adds specific, truthful detail and addresses the actual professor by name/designation, since a vague 'unforeseen circumstances' reads as evasive and unverifiable\):

__Edited Final Version:__

"Dear Dr\. \[Surname\], I am writing to request a one\-day extension on the Data Structures lab report \(due Friday\), as our lab system was down for maintenance on Wednesday afternoon, delaying my final test runs\. I would be grateful for submission until Saturday evening\. Thank you for considering this request\. Regards, \[Full Name\], Roll No\. \[XXXX\]"

__*Explanation of Approach*__

The AI draft provides correct structure and formal tone instantly, but the student must replace generic, unverifiable phrases \('unforeseen circumstances'\) with specific, true, checkable details, and add identifying information \(name, roll number\) the AI could not have known — this is the core of the 'draft, then verify and personalise' workflow from Section 4\.2\.
